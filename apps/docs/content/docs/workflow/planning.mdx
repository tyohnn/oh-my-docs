## Intent

Planning artifacts (PRD, story, SPEC, ADR, plan) are **optional durable
indexes** for agents and future readers. They are not a required sequence
before implementation (`ADR-008`, `SPEC-docs-first-development`).

Read `.omd/project.json` `contentSource.ssot` (`local` | `notion`; missing
means `local`) when editing handbook content so writes go to the selected
SSOT.

## When to write

Write or update a catalog row when:

- a decision should survive this chat, or
- another agent will need the same context cold.

Skip ceremony for small fixes and exploratory work. Prefer updating an
existing stable ID over minting a duplicate.

## Suggested shapes (optional)

| Need | Catalog |
|---|---|
| Why we chose X | ADR |
| Observable contract | Data model / system (API) spec |
| Initiative outcome | PRD + stories (if useful) |
| Bounded work notes | Plan (informational; not a merge key) |

Local SSOT keeps the full Fumadocs section tree. Notion SSOT is Home + inline
catalog DBs only.

## Tooling

```bash
node <skill>/scripts/omd.mjs new prd|story|spec|plan|adr --title "…" --yes
pnpm check:planning   # optional graph/nav hygiene when catalogs exist
```

There is no `check:docs-first` gate and no requirement to merge planning
before code.
