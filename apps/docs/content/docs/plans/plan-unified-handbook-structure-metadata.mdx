## Scope

1. Merge `DEFAULT_IA_SECTIONS` / `DEFAULT_CATALOGS` and `notion-ia-graph.json`
   into one skill IA graph (`handbook-ia-graph.json`) with `localPath`,
   `metaRole`, and catalog `writeTarget` / `databaseKey` / `forbiddenParents`.
2. Stamp the graph into `.omd/project.json` `informationArchitecture` on adopt.
3. Generate local Fumadocs `meta.json` skeletons from the graph on adopt/sync;
   keep catalog detail `pages[]` project-owned.
4. Point Notion `planProvision` / loaders at the unified graph.
5. Document and enforce catalog write destinations (Planning ≠ Plans; DB row /
   local catalog folder, not section child pages).
6. Dedup `apps/docs/lib/source.ts` catalog config against the same contract.

## Implementation sequence

1. Land this ready plan and SPEC/story updates (docs-first).
2. Author unified graph; align Domain; map `adr` ↔ `pages.adrs`; no default Spec CLI.
3. Replace dual loaders; stamp IA on adopt; generate meta skeletons.
4. Wire Notion provision to the graph; keep chrome validators.
5. SKILL Hard rules + AGENTS marker + catalog-writes reference; create-document
   / `planCreateDocument` tests.
6. Dedup docs catalog list; sync plugins; mark done after verification.

## Migration and compatibility

- Existing projects keep working; next adopt/sync refreshes structure meta.
- Catalog detail `meta.json` page lists are not wiped by sync.
- Notion workspaces with misplaced child pages are not auto-moved.

## Risks and rollback

- Over-generating `meta.json` could clobber catalog page lists — sync must only
  update structure skeletons / known omdGenerated paths.
- Rollback: restore prior `notion-ia-graph.json` + `DEFAULT_*` constants.
