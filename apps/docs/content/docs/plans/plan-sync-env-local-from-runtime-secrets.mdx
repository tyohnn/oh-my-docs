## Scope

Add a small setup helper for Cursor Cloud (and local) environments where
Supabase publishable values are available as **runtime secrets / process
environment variables**, but the docs app expects them in
`apps/docs/.env.local`.

1. Script reads key **names** from `apps/docs/.env.example`.
2. For each key present (non-empty) in `process.env`, write it to
   `apps/docs/.env.local`.
3. Merge with an existing `.env.local` (do not wipe unrelated keys); skip
   already-set keys unless `--force`.
4. Wire `pnpm` scripts; document the Cursor Cloud install/setup usage in
   `AGENTS.md`.
5. Unit-test parsing/merge behavior without printing secret values.
6. Commit `.cursor/environment.json` so Cloud Agents run `pnpm install` as
   `install` and materialize `.env.local` from runtime secrets on each boot
   via `start` (`sync-env-local --best-effort --force`). Prefer this over
   npm `postinstall` and over editing the personal dashboard env (no agent
   write API for personal/db-managed environments).

Out of scope: changing Fumadocs to runtime REST reads; committing secrets;
service_role keys; Cursor dashboard MCP writes (read-only).

## Implementation sequence

1. Land this ready plan (docs-only).
2. Add `apps/docs/scripts/sync-env-local.mjs` (+ tests).
3. Add `sync:env` scripts on the docs package and repo root.
4. Clarify `.env.example` comments for Cloud runtime-secret naming.
5. Note the setup command under Cursor Cloud instructions in `AGENTS.md`.
6. Add `.cursor/environment.json` with `install` / `start` as above; keep
   `--best-effort` so missing secrets do not fail environment boot.

## Verification

- `node --test apps/docs/scripts/sync-env-local.test.mjs`
- `pnpm --filter @oh-my-docs/docs test`
- `pnpm check:planning`
- Dry-run with fixture env: writes only keys named in `.env.example`
- Confirm `.cursor/environment.json` is valid JSON and `start` invokes the
  sync script with `--best-effort --force`

## Migration and compatibility

No behavior change for projects that already maintain `.env.local` by hand.
Missing runtime secrets produce warnings and leave those keys unset.
When `.cursor/environment.json` is present, Cursor prefers the repo-file
environment over a personal/db-managed snapshot for this repo.

## Risks and rollback

- Accidental logging of secret values — mitigate by logging key names only.
- `start` is non-blocking; sync is a short file write so agents still get
  `.env.local` before typical `dev`/`build` usage.
- Rollback: remove the script, `sync:env` entries, and/or
  `.cursor/environment.json`.

## Completion criteria

- Running the script with secrets in the environment produces a usable
  `apps/docs/.env.local` for `pnpm --filter @oh-my-docs/docs dev|build`.
- Cloud Agents materialize `.env.local` via `.cursor/environment.json`
  `start` without a manual `pnpm sync:env`.
- Plan stage moves to `done` after verification.
