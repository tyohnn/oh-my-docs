## Vision

Builders should not lose product intent in tickets and chats, but they also
should not be forced through a heavy docs ritual before every change.

Oh My Docs gives coding agents a **local Fumadocs handbook** or a **simple
Notion page of catalog databases**. Humans can keep day-to-day work on a light
task board; when someone is curious, the agent explains from the repo and
catalogs.

## Principles

1. Cold-start agents need durable indexes more than humans need a second handbook.
2. Stable IDs beat filename coupling when you do write catalogs.
3. Automation must not block shipping.
4. Browser pages and `.md` twins are the same source (local SSOT).
5. One skill (`oh-my-doc`) drives the runtime; people do not need a public CLI.
6. Exactly one content SSOT per repo: `local` or `notion`.

## How it ships

- **Local:** handbook MDX in `docs/` or `apps/docs`, Fumadocs from npm, UI
  vocabulary from the skill template into `packages/docs-ui` on adopt.
- **Notion:** Home + inline catalog DBs (ADR, specs, plans, …) — no Vision /
  Workflow chrome in Notion.

## Not in scope

- Supabase handbook SSOT (deleted)
- Docs-first merge gates (deleted)
- Hosted multi-tenant persistence, auth platform, or web handbook editor
- Bidirectional local ↔ Notion sync
- Soft migration / compatibility shims for removed paths
