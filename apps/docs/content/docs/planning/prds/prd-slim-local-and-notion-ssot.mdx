## Problem

Supabase SSOT, revalidate setup, and docs-first gates made the product heavier
than its use. Soft migration would leave the weight in place.

## Outcome

- SSOT: **`local`** or **`notion`** only.
- **Local:** full Fumadocs MDX handbook.
- **Notion:** Home + inline catalog DBs only (no Vision / Workflow).
- **Hard-delete** Supabase handbook SSOT, remote loaders, and Vercel
  revalidate/deploy content-port features.
- **Hard-delete** planning/development gates (`Plan:`, `check:docs-first`,
  required artifact chain). No no-op shim.

## Goals

- One SSOT per repo.
- Notion is a catalog index, not a second full handbook.
- Agents ship without gate ceremony.
- Dead Supabase/gate code and catalog pages leave the tree.

## Non-goals

- Soft migration / dual-run / compatibility shims
- Auto-export of Supabase rows
- Bidirectional local ↔ Notion sync
- Web handbook editor

## Included stories

- `US-slim-local-or-notion-handbook-ssot`

## Success measures

- No supabase SSOT path in runtime or docs app.
- No `check:docs-first`.
- Notion provision is catalog-only.
- Dogfood `.omd` is `local` after implementation.
