## Scope

Covers skill install plus the skill-era runtime actions that inspect, adopt,
check, and refresh the planning UI vocabulary snapshot and managed IA files.
Does not cover Fumadocs shell package versions on npm. Product intent still
comes from this handbook and root `AGENTS.md` (with `CLAUDE.md` as a bridge).

## Install

```bash
npx skills add ssota-labs/oh-my-docs --skill oh-my-doc -y
```

`npx skills add` defaults to **symlinks** from each agent discovery path to one
canonical skill copy (usually under `.agents/skills/` or `~/.agents/skills/`).
Prefer `-a <host>` when only one agent is needed. Do not pass `--copy` unless
the environment cannot use symlinks. Adopt must not create three independent
full copies of the skill tree.

| Host | Project | User |
|---|---|---|
| Cursor | `.cursor/skills/oh-my-doc` (symlink) | `~/.cursor/skills/oh-my-doc` |
| Codex / agents | `.agents/skills/oh-my-doc` (canonical) | `~/.agents/skills/oh-my-doc` |
| Claude Code | `.claude/skills/oh-my-doc` (symlink) | `~/.claude/skills/oh-my-doc` |

In this repository the canonical skill source is `skills/oh-my-doc`. Optional
host plugin wrappers under `plugins/{cursor,codex,claude-code}` mirror it.

## Interface

| Action | Role |
|---|---|
| `inspect --json` | Report docs/UI/`.omd` presence and UI snapshot health hints |
| `check --json` | Fail when `.omd` is missing, vocabulary contract is incomplete, or UI snapshot is missing/stale vs skill template |
| `adopt --yes` | Create missing UI files from the skill template; skip identical files |
| `adopt --yes --force` | Also overwrite UI files that differ from the skill template |
| `sync --yes` | Refresh managed IA/`AGENTS.md`/`CLAUDE.md` markers only (not UI files) |

Runtime entrypoint: `node <skill>/scripts/omd.mjs <action>`.

## Behavior

1. **Greenfield SSOT** — first adopt requires `--ssot local|notion`. Without it
   the runtime returns `needsSsot` and does not write.
2. **Missing UI package or files (local only)** — `doctor`/`inspect` note a
   missing UI path; `check` includes a problem; `adopt --ssot local` creates
   files from `<skill>/templates/default/packages/docs-ui` into the configured
   `ui` path (default `packages/docs-ui`). Notion adopt skips this.
3. **Identical snapshot** — `adopt` skips with reason `UI snapshot up to date`.
4. **Divergent files** — without `--force`, `adopt` records a conflict/skip;
   `check` reports staleness so agents can ask before forcing.
5. **Forced refresh** — `adopt --force` updates divergent skill-template UI
   files and refreshes `.omd` state digests related to the snapshot.
6. **Skill vs project** — installing/updating the skill alone does not mutate
   the project; agents must run `adopt`/`check` against the project.

## Data and invariants

- `.omd/project.json` declares `ui.distribution: skill-template` and the
  vocabulary list.
- `.omd/state.json` records `uiSnapshot.vocabularyDigest` (and related file
  digests when written by adopt).
- Project UI lives under the configured `paths.ui`; the skill template remains
  the source of truth for refresh.

## Errors

| Condition | Signal |
|---|---|
| No `.omd/project.json` | `check` problem: run adopt first |
| UI path missing | doctor/inspect missing note; check problem |
| Vocabulary name missing from contract | `check` problem naming the component |
| Template file differs and not forced | adopt conflict/skip; check stale problem |

## Compatibility

- Brownfield projects that already customized `packages/ui` or
  `packages/docs-ui` must use `--force` knowingly; adopt never silently
  overwrites divergent files without `--force`.
- Legacy `packages/ui` remains a valid detected UI path.
- `sync` must not rewrite UI vocabulary files.

## Acceptance criteria

- `check --json` returns `ok: false` with an explicit UI missing/stale problem
  when the project snapshot does not match the skill template for managed UI
  files (identical content is not stale).
- `adopt --yes` restores missing files without `--force`.
- `adopt --yes --force` makes the project UI match the skill template again.
- Machine-readable JSON includes enough detail for an agent to choose adopt vs
  adopt `--force`.
