## Scope

Defines provider selection in `.omd/project.json` and operational provider
observations in `.omd/state.json`.

## Project contract

The next contract version adds:

```json
{
  "contentSource": {
    "ssot": "local"
  }
}
```

or:

```json
{
  "contentSource": {
    "ssot": "notion",
    "notion": {
      "rootPageId": "stable-provider-id",
      "rootPageUrl": "https://www.notion.so/...",
      "schemaVersion": "1.0"
    }
  }
}
```

`rootPageId` and `rootPageUrl` identify the handbook **Home** page
(`pages.home`) but grant no access. Tokens, OAuth secrets, cookies, and MCP
session data are forbidden.

For `ssot: notion`, local docs-app paths and UI vocabulary snapshots are not
required. For `ssot: local`, `paths.ui` defaults to `packages/docs-ui`.

## State contract

Notion state contains:

- schema digest and last observed time
- stable OMD key → page/database ID mappings (including `pages.home` → root)
- last successful manifest digest
- incomplete operation IDs for safe retry

State is rebuildable and never authoritative content.

## Compatibility

- A version `1.0` project without `contentSource` is interpreted as `local`.
- Migration writes the explicit local selection without altering docs.
- Existing local paths, UI snapshot, ownership, and lifecycle contracts remain
  valid for local projects.
- Greenfield adopt without an explicit `ssot` flag is rejected (`needsSsot`).

## Validation

- Exactly one `ssot` value is present.
- Notion requires a parseable root ID and canonical root URL mapped as Home.
- Local requires configured content paths and a UI vocabulary path.
- Notion must not require a local UI package.
- State mappings must reference known IA/catalog/document keys.
- Project and state digests must agree.

## Acceptance criteria

- Provider choice round-trips through project metadata.
- No secret appears in project/state JSON or logs.
- Legacy projects validate as local.
- Notion projects validate without local docs/UI packages.
- Adopted projects instruct agents (via the managed `AGENTS.md` marker) to read
  `.omd/project.json` `contentSource.ssot` and treat that provider as the only
  handbook SSOT.
- During product conversations about vision, roadmap, PRDs, stories, Domain,
  specs, ADRs, or plans, agents must check whether the agreed outcome already
  exists in the SSOT and create or update the matching handbook artifacts
  there — not leave decisions only in chat.
