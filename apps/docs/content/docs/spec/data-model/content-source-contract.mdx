## Scope

Defines provider selection in `.omd/project.json`, operational provider
observations in `.omd/state.json`, and how **structure metadata** relates to
the content SSOT. Allowed SSOTs are **`local` and `notion` only**
(`ADR-008`). Supabase field shapes in older documents are superseded.

## Structure metadata vs content SSOT

| Layer | Authority | Examples |
|---|---|---|
| Content SSOT | `contentSource.ssot` (`local` \| `notion`) | MDX bodies or Notion page/DB rows |
| Structure metadata SSOT | Skill IA graph stamped into `.omd/project.json` `informationArchitecture` | Sections, catalogs, provider keys, local paths, write targets |
| Provider state | `.omd/state.json` (rebuildable) | Provider key → object ID mappings, digests |

Local projects use the **full** handbook IA graph (Fumadocs sections).
Notion projects use the **slim** catalog-only IA graph (Home + inline DBs).
Fumadocs `meta.json` files remain on disk for local projects. Catalog
**detail** `pages[]` lists stay project-owned. Notion catalog entries are
rows in the catalog inline database — never ad-hoc child pages of a
narrative section.

## Project contract

```json
{
  "contentSource": {
    "ssot": "local"
  }
}
```

or:

```json
{
  "contentSource": {
    "ssot": "notion",
    "notion": {
      "rootPageId": "stable-provider-id",
      "rootPageUrl": "https://www.notion.so/...",
      "schemaVersion": "1.0"
    }
  }
}
```

`rootPageId` and `rootPageUrl` identify the handbook **Home** page
(`pages.home`) but grant no access. Tokens, OAuth secrets, cookies, and MCP
session data are forbidden.

For `ssot: notion`, local docs-app paths and UI vocabulary snapshots are not
required. For `ssot: local`, `paths.ui` defaults to `packages/docs-ui`.

`ssot: supabase` is **invalid** on new contracts. Existing dogfood must
migrate to `local` or `notion` (implementation plan).

## State contract

Notion state contains:

- schema digest and last observed time
- stable OMD key → page/database ID mappings (including `pages.home` → root)
- last successful manifest digest
- incomplete operation IDs for safe retry

State is rebuildable and never authoritative content.

## Compatibility

- A version `1.0` project without `contentSource` is interpreted as `local`.
- Migration writes the explicit local selection without altering docs.
- Greenfield adopt without an explicit `ssot` flag is rejected (`needsSsot`)
  with options `local` and `notion` only.
- Projects that still record `supabase` fail `check` with a migration hint.

## Validation

- Exactly one `ssot` value is present (`local` or `notion`).
- Notion requires a parseable root ID and canonical root URL mapped as Home.
- Local requires configured content paths and a UI vocabulary path.
- Notion must not require a local UI package.
- State mappings must reference known IA/catalog/document keys.
- Project and state digests must agree.
- No `contentSource.supabase` object is accepted.

## Acceptance criteria

- Provider choice round-trips through project metadata for `local` | `notion`.
- No secret appears in project/state JSON or logs.
- Legacy projects without `contentSource` validate as local.
- Notion projects validate without local docs/UI packages.
- Managed `AGENTS.md` instructs agents to treat the selected provider as the
  only handbook content SSOT.
- Documentation is always first: durable decisions go into the selected SSOT.
- Catalog entries write to the catalog store (local folder + `meta.json`, or
  Notion inline DB).
