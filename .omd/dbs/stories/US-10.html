US-10

Split product IA into one row per information unit

summary
As an agent authoring a host handbook, I create one IA-* row per information unit so the catalog is a graph, not a dumped sitemap.
PRD
PRD-7
Features

Persona

Coding agent using the Oh My Docs skill in a host product repo.

Narrative

When I model product information architecture, I call omd new ia once per unit (Inbox, Thread, Settings, …), set unitType, and link parent/children and pages. I do not create a single “전체 IA” row.

Acceptance

  • IA template and skill tell the agent: one row = one information unit.
  • Each IA row has required unitType (허브 / 목록 / 상세 / 작성 / 설정 / 탐색, or English aliases).
  • omd check rejects whole-product IA titles such as “Information architecture”, “전체 IA”, “사이트맵”.
  • Parent/children relations target other IA rows; pages attach to the unit they belong to.
