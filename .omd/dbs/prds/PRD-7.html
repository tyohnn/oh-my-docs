PRD-7

Product IA units and viewport wireframes

status
active
summary
One IA row per information unit; layout/screen-state wireframes always sit on top as mobile + desktop.
Stories
US-10 US-11 US-12
Features
Release

Problem

When agents use Oh My Docs in a host project they often write the entire product sitemap into a single IA-* row, and they place layout/screen-state wireframes anywhere in the document. Viewport coverage is inconsistent — some projects get one mock, some mix shell/body instead of mobile/desktop.

Outcome

  • Each product IA catalog row is one information unit, not the whole IA tree.
  • Layout and screen-state wireframes always appear immediately after the doc header, before narrative body.
  • Every layout and screen-state has both a mobile and a desktop wireframe.
  • omd check rejects whole-tree IA titles and missing/misplaced viewport wireframes.

Goals

  • Make the IA template and skill text impossible to read as “dump the sitemap in one file”.
  • Replace the required wireframe split from shell/body to mobile/desktop (see ADR-7).
  • Keep check machine-enforceable so project-to-project drift stops.

Non-goals

  • Auto-splitting an existing mega-IA file into units (agents rewrite rows).
  • Generating pixel-perfect UI; wireframes stay structural mocks.

Included stories

US-10, US-11, US-12.

Success measures

  • omd new ia --title "Information architecture" fails check; omd new ia --title "Inbox" passes with unitType.
  • omd new layout / omd new screen-state emit mobile then desktop wireframes above main.omd-doc-body.
  • Check fails if a wireframe sits inside or after the narrative body, or if either viewport is missing.
