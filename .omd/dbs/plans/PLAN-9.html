Goal

Stop host agents from stuffing the whole sitemap into one IA row, and make layout/screen-state wireframes a stable mobile+desktop pair at the top of the document.

Approach

Canonical skill files under skills/oh-my-doc: rewrite IA and layout/screen-state templates, document the contract, enforce it in html-document / validateHtmlPlanning, add tests, then pnpm sync:skills.

Steps

  1. Update IA template (unitType, parent/children, one-unit copy) and layout/screen-state templates (mobile then desktop above body).
  2. Update SKILL.md, html-document-contract, document-contracts, planning-workflow, local-html-ia-graph relations, CSS device frames.
  3. Parse wireframe tokens and placement; reject whole-tree IA titles and missing unitType.
  4. Runtime tests for new + check failures; consumer-agent simulation in a throwaway adopt dir.
  5. Copy CSS into dogfood .omd/assets and sync plugin wrappers.

Risks

Host projects with shell/body-only mocks will fail check until they add viewport sections — that is intended.

Verification

  • node --test skills/oh-my-doc/tests/*.test.mjs
  • pnpm check:planning and pnpm check:skills
