ADR-7

Wireframes are mobile and desktop viewports

stage
accepted
summary
Required wireframe split is mobile + desktop, not shell + body.

Context

Layout and screen-state templates previously required data-omd-wireframe="shell" and "body". Host projects still placed mocks inconsistently, and they did not reliably produce both phone and desktop views.

Decision

The required pair is mobile then desktop. Chrome versus body is drawn inside each viewport mock (sidebar, top bar, content blocks). Shell-only layouts still emit both viewports — they show chrome at each size, not a separate body skeleton.

Consequences

  • Check enforces the two viewport tokens and that all wireframes sit above main.omd-doc-body.
  • Existing host docs that only have shell/body mocks fail check until rewritten.

Alternatives considered

  • Keep shell/body and add mobile/desktop (four mocks) — too noisy for a catalog row.
  • Guidance-only, no check — already failed across projects.
