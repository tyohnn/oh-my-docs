IA unit rows and viewport wireframe contract

stage
accepted
specType
data-model
summary
IA row = one unit with unitType; layout/screen-state require mobile+desktop wireframes before the body.

Contract

Local HTML catalogs encode product IA as many ia documents and encode layout/screen-state mocks as two required viewport wireframes. Canonical skill text lives in skills/oh-my-doc/references/html-document-contract.md.

Entities

  • ia — one information unit per file under .omd/dbs/ia/IA-*.html
  • layout / screen-state — one layout or one state per file; each must expose viewport wireframes

Fields

  • IA unitType: 허브 | 목록 | 상세 | 작성 | 설정 | 탐색 (aliases: hub, collection, object, flow, settings, cluster)
  • IA relations: parent → ia, children → ia[], pages → page[]
  • Wireframe: <section class="omd-wireframe" data-omd-wireframe="mobile|desktop">

Invariants

  • IA title must name the unit. Forbidden whole-tree titles: Information architecture, 전체 IA, IA 구조, 정보구조, 사이트맵, sitemap (and close variants).
  • Layout and screen-state documents include both mobile and desktop wireframe sections.
  • Every .omd-wireframe appears after header.omd-doc-header and before main.omd-doc-body.
  • Each viewport uses the matching device wrapper (omd-wire-device-mobile / omd-wire-device-desktop) and at least one kit block (omd-wire-block, omd-wire-row, omd-wire-field, omd-wire-status, or omd-wire-actions).
  • Authoring rules live in skills/oh-my-doc/references/wireframe-authoring.md.

Acceptance

  • omd check / validateHtmlPlanning report the invariants above.
  • omd new ia|layout|screen-state templates satisfy the invariants.
